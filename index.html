Accountability · SDPE

사람이 돌리던 SAR 처리를 무인으로 바꿨습니다

PM · Architecture · MSA · EDA · 진행 중

Problem

SAR 처리의 각 단계를 담당자가 명령을 순서대로 돌리며 수작업으로 넘겼습니다. 단계마다 대용량 산출물을 NAS에 쓰고 다시 읽어 한 장면에 10분 이상 걸렸습니다.

Solution

사용자가 DAG로 단계를 구성하면 전 과정이 자동 실행되게 설계했습니다. 단계 간 데이터는 메모리로 넘겨 NAS I/O를 없애고, 영상을 Azimuth 블록으로 나눠 GPU 병렬 처리했습니다. 실패 단계는 이벤트 큐에서 재시도됩니다.

Result

40초대SAR 처리 · 이전 10분+
15×처리 성능

MSA · EDA · DAG · Event Queue · GPU · Kubernetes

Appendix · 파일 전송 엔진

중간에 죽어도 이어지는 50GB 전송을 만들었습니다

Tech Lead · 설계 주도 · Windows API 전송 엔진

Problem

NAS 권한을 부여하는 방식이라 대용량 전송이 느리고 서버 한 대에 부하가 몰렸습니다. 전송 중 서버가 죽으면 처음부터 다시 올려야 했고, 증설이나 부하 분산 수단도 없었습니다.

Solution

OneDrive처럼 Windows API 기반 전송 엔진을 직접 만들고 파일을 청크로 나눠 병렬 전송했습니다. k8s 오토스케일과 큐로 부하를 나누고, 전송 상태를 Redis에 보관해 서버가 죽어도 이어서 전송합니다.

Result

50GB 전송이 1GbE 단일 기준 약 20분에서 수 분으로 줄었습니다. 중간 서버가 죽어도 마지막 지점부터 이어서 전송합니다.

Windows API · 청크 병렬 · Kubernetes HPA · Queue · Redis · Portal SSO 자동 로그인
